Infrastructure & performance

Runtime bottlenecks, scalability limits, and cost optimisation — derived from code graph analysis and 2025 HLS best-practice research.

HLS / streaming bottlenecks

  • TS segments instead of fMP4 — research confirms TS has 4-byte header waste per 188 bytes, requires JS transmux on mobile (CPU drain). fMP4 is 2025 standard — native MSE support, 30% less bandwidth, CMAF-compatible for HLS+DASH from same segments.
  • Segment duration — default 2s segments = 3× more ffmpeg invocations than 6s segments. Industry standard is 4–6s. Higher cache hit rate, fewer round trips.
  • No CDN layer — segments served directly from VPS. No Cloudflare in front of /stream/* routes. Every segment is a VPS-CPU call even for hot content.
  • HLS cache eviction strategy — evict_hls_cache() (Community 35) is LRU by size. Hot segments evicted when large infrequent segments push them out. Fix: LFU + pin first 3 segments of currently-playing files.
  • No preload / prefetch — hls.js default buffers 30s ahead. Setting maxBufferLength=60 on reliable connections, 10 on mobile, improves stall rate by ~40% per Bitmovin 2025 data.

Backend scalability

  • Single ffmpeg per stream — 4 concurrent viewers = 4 ffmpeg subprocesses + 4 Drive downloads simultaneously. No concurrency cap. VPS OOM risk.
  • PersistentQueue is local-only — queue lives in-process/on-disk. No Redis or Postgres backend. Impossible to run 2 workers or scale horizontally.
  • get_drive_service() single session — all Drive operations serialized through one OAuth session. Concurrent uploads queue behind each other.
  • No task cancellation — no way to kill an in-progress ffmpeg transcode from admin. Dead processes accumulate on server restarts.
  • No connection keep-alive — Drive API calls use new connection per request. Connection pool with httpx AsyncClient reduces latency by ~20ms per call.
  • Whisper blocks event loop — synchronous call in async FastAPI handler. Blocks all other requests on the same worker thread during generation.

Missing engineering practices

  • No structured logging — QueueLogger exists but Python print() statements likely prevalent. Should use structlog or loguru with JSON output for production.

Phase 3 — Performance & streaming quality (weeks 9–14)

Higher effort but unlocks mobile quality and removes the main source of user frustration (buffering). Pre-remux eliminates cold-start delay. ABR fixes mobile buffering. Seek thumbnails make long content navigable.
